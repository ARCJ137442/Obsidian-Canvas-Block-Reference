# 元白板交互契约与验收

> 最后更新：2026-10-18

## 参照与范围

以当前 Obsidian 原生 Canvas 的阅读、平移和缩放行为为参照。元白板是只读关系图，节点拖动仅保存 ARC 自己的固定位置；不因此复制原生 Canvas 的正文编辑、框选、新增节点或 Undo 数据格式。

0.6.1 的前进、回溯、最近成功跳转排序已由用户人工验证。0.6.2 的元白板键鼠与触摸修复须分别记录自动验证和真机人工验证，不能把前一版本的人验结论扩大到新交互。

用户已在 0.6.3 部署后实测确认节点双击进入白板和缩放正常，并授权发布正式 fix。此确认限定于这两项功能，不扩展为全部移动设备手势均已验收。

## 已复现的原因

- 主窗口与 popout 的 `performance.timeOrigin` 不同。旧代码用全局 `performance.now()` 开始动画，再接收目标窗口的 rAF 时间戳；实测两个时钟差约 2955ms，首帧把 1 倍放大请求错误地钳制成 0.28 倍。动画时间必须来自同一 Window，且进度限定在 0–1。
- 双指缩放保存初始中心和平移，却用不断变化的当前缩放作为基准分母。固定中心连续从 1 放大到 1.1、1.2 时，原应保持的世界坐标 `(280, 370)` 漂移到约 `(254.55, 336.36)`。应先确定手势开始时中心对应的世界坐标，再把它映射到当前双指中心。
- 原生 `.canvas-wrapper` 带 `data-ignore-swipe="true"`。当前宿主的 touchstart 手势入口沿祖先检查此标记，命中则不启动侧栏、下拉动作或双指历史滑动。仅设 `touch-action: none` 不会自动关闭宿主自己实现的手势。

这些结论来自当前安装的宿主代码和 CLI 运行时；它们是兼容边界，Obsidian 升级后需复核，不能当作永久公开 API 保证。

## 操作契约

### 0.6.3：捕获表面必须保留点击目标

用户已确认 0.6.2 滚轮正常，但真实鼠标双击失效。CLI / CDP 输入复现：卡片的 pointerdown 把指针捕获到 viewport，浏览器随后生成的 pointerup、click、dblclick 也落到 viewport，卡片没有收到双击。此前直接在卡片 dispatch dblclick 的探针绕过了这一步，不能作为真实双击通过的证据。

- 鼠标 / 触笔节点手势由卡片本身捕获；触摸和画布平移仍由 viewport 捕获，状态机与输入范围不变。
- 记录每个指针实际使用的捕获元素，在失焦 / 关闭时释放该元素；不能只尝试释放 viewport 的捕获。
- 正常 pointerup 后浏览器会发出 lostpointercapture。只对仍在进行的手势执行取消，避免把已经完成的首次触摸记录清空，破坏双 tap。
- `scripts/test-meta-canvas-native-pointer.mjs` 使用 CDP 的真实鼠标按下 / 弹起，由浏览器生成 click / dblclick；检查单击、双击、拖动后再双击，以及实际同标签页进入正确原生 Canvas。触摸释放顺序与滚轮为明确标注的合成事件检查，不宣称真机通过。

通过资源采样器运行（不新建窗口，需要已有 popout）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/measure-command.ps1 -Label native-pointer-main -Command "node scripts/test-meta-canvas-native-pointer.mjs --vault life-panel --window main"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/measure-command.ps1 -Label native-pointer-popout -Command "node scripts/test-meta-canvas-native-pointer.mjs --vault life-panel --window popout"
```

整个脚本及其 CLI 子进程统一采样；脚本自动恢复活动页面、关闭临时标签并解绑自己创建的 CDP session。默认用 PATH 中的 Obsidian CLI，也可通过 `OBSIDIAN_CLI` 指定可执行文件。

| 输入 | 预期 |
|---|---|
| 普通滚轮 / 触控板双轴滚动 | 平移画面 |
| Shift + 纵向滚轮 | 横向平移；已有横向 delta 不重复转换 |
| Ctrl / Meta + 滚轮 | 按鼠标所在位置缩放；优先于 Shift，连续输入累计目标 |
| 鼠标中键、右键拖动 | 在空白、卡片或连边上均平移 |
| Space + 主键拖动 | 视口获得焦点时临时平移；输入框和其它页面不接管 |
| 主键拖动卡片 | 移动并固定该白板卡片 |
| 单指拖动 | 平移，包括从卡片或连边开始 |
| 长按卡片后拖动 | 移动并固定卡片 |
| 双指 | 按双指中心缩放，同时允许中心平移；松开一指可连续平移 |
| 点击空白 / Escape | 取消选择 |
| 单击卡片 / 连边 | 持久选择，悬浮只局部高亮 |
| 双击卡片 | 打开该白板 |
| 双击连边 / 连边 Enter | 执行该关系的入口选择流程 |

滚轮的 line/page 单位须归一化。放大缩小有边界，但达到边界时中心不应跳动。视口缩放和平移不修改源 Canvas，也不改变固定节点的世界坐标。

## 生命周期与隔离

- 指针、动画、计时器和 Window 监听均归属于当前视口。
- 指针取消、丢失捕获、窗口失焦、页面隐藏、重绘、关闭和插件重载均结束未完成手势；取消不能保存半次节点拖动。
- 后台关系刷新保留用户视口；初次适配、显式适配、布局切换和重置才可重新适配。
- 旧 rAF / 首次适配 / 异步查询不能在用户已经交互、视口重建或页面关闭后回写。
- 手势阻断只作用于元白板绘图区；详情滚动、工具栏、菜单、输入和其它页面照常工作。
- 不更改 Obsidian 的移动仿真、系统缩放或无关插件；操作系统屏幕边缘手势须与应用内部滑动区分。

## 验证层次

1. **单元测试**：世界坐标锚点、连续缩放、移动中心、边界、滚轮单位与累加；真实事件状态机的拖动、触摸转换、取消、点击抑制和监听清理。
2. **桌面 CLI**：在 Life Panel 已启用 ARC 的主窗口与 popout 各自验证 DOM 事件、变换数值、控件负路径和重载清理。合成 PointerEvent 可验证状态机，不能证明真实 WebView 的手势仲裁。
3. **手机 / 平板人工**：验证真实触摸、系统点击合成、侧栏与下拉动作抑制，并与同设备原生 Canvas 对照。

所有测试、构建和 CLI 探针经 `scripts/measure-command.ps1` 采样并记入 `tests/resource-usage.md`。探针使用临时标签，结束恢复活动页面、测试补丁与布局状态；源 Canvas 文件前后核对哈希。错误按栈帧归因，不清空日志掩盖外部异常。

## 人工验收顺序

1. 确认插件实际加载 **0.6.3**。跨设备同步 `main.js`、`manifest.json`、`styles.css` 后重载；确认没有开启移动端仿真。
2. 先在同设备原生 Canvas 完成一次平移和双指缩放，再打开元白板比较。
3. 桌面将鼠标放在一张容易识别的卡片上，连续 Ctrl + 滚轮放大、缩小和快速反向；卡片应留在鼠标附近，不回弹到固定比例。普通滚轮、Shift + 滚轮与中 / 右键拖动分别验证。
4. 在主窗口、分栏及已有独立窗口重复关键操作；失焦后回来不应持续拖动或继续执行旧动画。
5. 手机和平板从绘图区内部单指上下、左右拖动，应只平移元白板，不唤出下拉动作、侧栏或历史导航。详情面板内仍应正常滚动。
6. 双指夹住某个卡片，反复开合并同时移动双指中心；该卡片应跟随中心。松开一指继续平移，再全部松开；不得跳到左上角或误选节点。
7. 从卡片开始短拖应平移；长按后拖动才移动并固定卡片。触摸取消、切换页面再回来不应保存未完成的拖动。
8. 检查单击选择、点击空白取消、双击打开、连边入口、工具栏适配与布局软 / 硬重置；最后确认原生白板及前进 / 回溯仍可用。

反馈请包含设备、系统、Obsidian / ARC 版本、主窗口或独立窗口、输入设备、起点位于空白 / 卡片 / 连边、完整操作顺序和预期 / 实际结果。验收状态按用户实际确认的功能范围记录；0.6.3 本轮双击与缩放已人工验收成功，正式发行，不能继续标成待人验。未来新增且尚未实测的交互单独记录。
